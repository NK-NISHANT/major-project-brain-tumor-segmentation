# BMAD-Style Adaptation

BMAD is optional. We do not need a methodology label just for appearance.

The useful idea is staged, artifact-driven work:
- PRD → what the system must accomplish
- Architecture → how it is structured
- Rules → hard constraints
- Phases → implementation sequence
- Design → visual/demo decisions
- Memory → current state and decisions
- Edge Cases → failure modes
- Experiment Protocol → scientific evaluation
- Codex Workflow → scoped AI coding tasks

## Why this helps
It prevents Codex from inventing architecture, preserves context across tools, reduces uncontrolled rewrites, improves reproducibility, and creates useful project documentation.

## Do not over-process
These are living documents. Update them when real decisions change; do not spend weeks writing process documents instead of building the system.
